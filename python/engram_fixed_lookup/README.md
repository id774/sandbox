# Engram Fixed Lookup

## Purpose

This deterministic NumPy experiment holds the reference-table bytes fixed
while changing Backbone weights and comparing candidate scores and the
`argmax` token. It separates byte equality, score equality, and token equality.

## Requirements

- Python 3.12
- NumPy 2.2.6

## Run

From the repository root on Linux or macOS:

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install numpy==2.2.6
python -B python/engram_fixed_lookup/engram_fixed_lookup.py
```

Run normally without `-O` so the built-in assertions execute. The script has
no command-line arguments or external data, reads no files, and makes no
network requests. Passing assertions and completion exit with status 0;
an assertion failure or unhandled exception exits nonzero.

## Checks and Expected Results

- `D_ORIGINAL` and `D_COPY` have identical dtype, shape, and C-order bytes.
- Changing one table element in `D_MODIFIED` makes the byte comparison false.
- `W_ORIGINAL` produces scores `A=2.0010`, `B=2.0000`, selecting `A`.
- `W_FLIP` keeps the reference bytes but produces `A=1.9990`, `B=2.0000`, selecting `B`.
- `W_KEEP` keeps the reference bytes but produces `A=2.0005`, `B=2.0000`, selecting `A`.
- Both modified Backbones produce scores different from the original.

Expected standard output:

```text
参照テーブル一致: True
変更した参照テーブルとの一致: False
元モデル: A=2.0010, B=2.0000, token=A
順位逆転: A=1.9990, B=2.0000, token=B
順位維持: A=2.0005, B=2.0000, token=A
スコア一致（順位逆転）: False
スコア一致（順位維持）: False
```

## Scope

The lookup uses a fixed row index, two `float64` arrays with little-endian
encoding (`<f8`), a two-candidate linear readout, and deterministic `argmax`.
The changed matrices are assigned directly, rather than generated by a
quantizer. This sample does not implement Engram's n-gram hashing, gating,
convolution, or MXFP8 storage, and it does not measure language-model answer
quality. The observed outputs are evidence only for the fixed numeric cases.

The corresponding discussion is in
[Engram のバイト一致だけでは回答品質を証明できない](https://blog.id774.net/entry/2026/11/02/5828/).
